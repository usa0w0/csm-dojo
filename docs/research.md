# 調査: CSM 試験の形式、出題範囲、問題の出典

調べた日: 2026-10-08

## 試験の形式

| 項目 | 内容 | 確かめ方 |
| --- | --- | --- |
| 実施団体 | Scrum Alliance | [1] |
| 問題数と形式 | 50問、選択式 | [1] |
| 制限時間 | 60分 | [1] |
| 合格ライン | 74% 以上（50問中37問正解） | [1] |
| 受け方 | オンライン。試験監督はなく、会場にも行かない | [1] |
| 受験回数 | 2回までは無料 | [1] |
| 出題の元 | CSM Learning Objectives とスクラムガイド | [1] |

[1] は Scrum Alliance のサポート記事。このページはブラウザー以外からの取得を拒むため（HTTP 403）、本文を直接は読めていない。上の内容は、Web 検索がこのページから抜き出した記述で確かめた。

確かめられなかったこと:

- 受験できる期間（研修の後、何日以内か）と、3回目以降の受験料。古い記事（2011年）には「60日以内に2回、3回目から 25 ドル」とあるが、今の公式の記載は読めていない。受験する人は、Scrum Alliance のダッシュボードの表示で確かめること
- 日本語で受験できるか、問題を飛ばして後で戻れるか
- 分野ごとの出題数の比率。公式の資料には見つからなかった

## 出題範囲

Scrum Alliance は、研修で扱う内容を2つの Learning Objectives（LO）で公開している。試験はこの LO とスクラムガイドを元に作られる [1]。どちらも 2022年1月版で、スクラムガイド 2020年11月版を基準にしている [2][3]。

Scrum Foundations Learning Objectives（24項目）[2]

1. Scrum Theory（7項目）: スクラムの定義、5つの価値基準、経験主義、三本柱、反復的で漸進的な進め方の利点、一部だけ導入した時の不利益、アジャイルソフトウェア開発宣言との関係
2. The Scrum Team（2項目）: 3つの責任の関わり方、機能横断型で自己管理型のチームの利点
3. Scrum Events and Activities（6項目）: タイムボックスの利点、スプリントの目的と長さ、4つのイベントの目的・参加者・順序・タイムボックス、プロダクトバックログリファインメント
4. Scrum Artifacts and Commitments（9項目）: 3つの作成物の目的と特徴、3つの確約（プロダクトゴール、スプリントゴール、完成の定義）、スプリントバックログの変え方、複数のインクリメント、完成の定義の育て方

CSM Learning Objectives（25項目）[3]

1. Scrum（16項目）: スクラムチーム、スクラムマスター、開発者、プロダクトオーナーの責任。プロダクトオーナーが1人である理由。各イベントの進め方。レトロスペクティブを省いた時の影響。デイリースクラムと進捗報告の違い。スプリントを中止する条件。完成の定義
2. Scrum Master Core Competencies（3項目）: ファシリテーションが役立つ場面、集団での意思決定の技法、ファシリテーション・ティーチング・メンタリング・コーチングの違い
3. Service to the Scrum Team, Product Owner, and Organization（9項目）: リーダーとしてのスクラムマスター、技術的負債、品質を上げる開発プラクティス、プロダクトオーナーへの支援、組織の障害物、障害物の扱い方、スクラム導入による組織の変化、プロジェクトマネージャーがいない理由

LO が元にしている資料は次の4つ [2][3]。

- アジャイルソフトウェア開発宣言（4つの価値と12の原則）
- スクラムの価値基準
- スクラムガイド
- Scrum Alliance の認定トレーナーたちの知見

LO の PDF は、Scrum Alliance のサイト上の元の URL が今は 404 になっている。上の内容は、認定トレーナーのサイトに置かれている同じ PDF（2022年1月版）で確かめた。これより新しい版があるかは確かめられていない。

## 問題の出典

次の2つだけを元に、問題と解説を書く。

| 資料 | 使い方 | ライセンス |
| --- | --- | --- |
| スクラムガイド 2020年11月版の日本語訳 [4] | 問題と解説の主な出典。根拠として節の名前を示し、該当する文を引用する | CC BY-SA 4.0。出典とライセンスを示せば、引用や改変ができる。作ったものも同じライセンスで公開する |
| アジャイルソフトウェア開発宣言と12の原則の日本語訳 [5][6] | 4つの価値と12の原則を問う問題の出典。根拠として、どの価値・原則かを示す | 全文をそのまま複製する場合だけ自由に複製できる。そのため、長い引用はせず、短い引用と出典へのリンクにとどめる |

決めたこと:

- 根拠は必ず上の2つのどちらかの該当箇所にする。スクラムガイドの節の名前（例:「スクラムイベント > デイリースクラム」）と、該当する文の引用を付ける
- LO の中には、スクラムガイドに書かれていない項目がある（集団での意思決定の技法、コーチングとメンタリングの違い、技術的負債、開発プラクティスなど）。これらは、スクラムガイドの記述を根拠にできる範囲だけを問題にする。研修で教わる個別の技法の名前を問う問題は作らない。講座の資料を使わない制約と、根拠を示す完了条件を守るため
- LO そのものは Scrum Alliance の著作物なので、文面は問題に写さない。分野の分け方と、問題が範囲を網羅しているかの確認にだけ使う
- 民間の模擬問題サイトや問題集の問題は写さない
- 問題と解説はこのリポジトリで書き下ろし、CC BY-SA 4.0 で公開する。サイトに出典とライセンスを表示する

この方針の弱いところ: スクラムガイドに書かれていない LO の項目（全49項目のうち1割ほど）は、問題が薄くなる。本番でそこから出た問題は、研修の内容で答えることになる。

## サイトでの分野の分け方

LO の分類に合わせて、5つに分ける。

| 分野 | 対応する LO | スクラムガイドの節 |
| --- | --- | --- |
| スクラムの理論と価値基準 | Foundations 1 | スクラムの定義、スクラムの理論、スクラムの価値基準、最後に。アジャイルソフトウェア開発宣言 |
| スクラムチーム | Foundations 2、CSM 1.1〜1.6 | スクラムチーム、開発者、プロダクトオーナー |
| スクラムイベント | Foundations 3、CSM 1.7〜1.14 | スクラムイベント（スプリントと4つのイベント） |
| 作成物と確約 | Foundations 4、CSM 1.15〜1.16 | スクラムの作成物（3つの作成物と3つの確約） |
| スクラムマスター | CSM 1.2、2、3 | スクラムマスター。ほかの節のうち、スクラムマスターのふるまいに関わる記述 |
